# v1.13.0 개발 로그

## 모바일 원격 생성 초기 테스트

- 모바일 씬 탭에서 PC의 프리셋·씬 목록을 읽고 2열/3열 격자로 전환할 수 있다. 목록은 12개씩 읽으며 프리셋·페이지를 넘겨도 웹 예약을 유지한다. 씬을 눌러 긍정·네거티브 프롬프트, 기존 캐릭터 매크로 선택과 NPC를 편집하고 최대 100장의 웹 큐를 한 번의 명령으로 실행한다. 완성 이미지마다 원본을 전달하고 해당 예약을 차감한다.
- 사용자 승인(2026-09-26)에 따라 편집과 예약은 웹 메모리·요청 snapshot에만 적용한다. PC 저장 씬·캐릭터 활성화·메인 파라미터·기존 PC 예약과 활성 프리셋은 변경하지 않으며 웹 새로고침 시 초안과 예약은 초기화된다. PC와 웹 씬은 같은 한 장 생성·참조·계정 전환·자동 저장 흐름을 사용한다. 새 이미지는 기존 씬의 실제 폴더 경로로 저장·등록되고 새 저장 schema·migration·원본 이동/삭제는 없다.
- PC가 생성 중이면 웹 생성은 거절하며 웹 씬 생성 중에는 PC 큐를 소비하지 않는다. 연결 폐기·만료·PC 취소 시 이후 회차를 멈춘다. 입력은 허용된 프롬프트·캐릭터 ID·NPC·예약 수만 검증하며 파일 경로나 임의 명령은 받지 않는다. 비용 조건이 바뀌면 시작 전에 거절하고 다시 확인하게 한다.
- 공통 씬 생성 경로의 PC/웹 교차 검사로 요청 반영·PC 데이터 보존·씬 폴더 재사용·동시 요청 거절·취소를 확인했다. 웹의 격자 전환, 편집 적용/취소, 캐릭터/NPC 선택, 페이지 간 예약과 단일 명령 다중 수신도 검사했다. 앱·웹 빌드는 통과했고 lint는 기존 ESLint 설정 누락으로 실행되지 않는다. 정적 웹은 별도 폴더에서 배포하며 앱 Git에 넣지 않는다. 실제 휴대폰 씬 생성은 변경된 PC 개발판 재시작 후 확인해야 한다. 실제 앱 버전은 1.12.0으로 유지한다.

- 모바일 프롬프트 펼치기·접기 영역의 터치 높이를 늘리고, 펼친 프롬프트가 상단 탭까지 덮으며 하단 조작 바를 제외한 화면 전체를 채우도록 UI 편의성을 개선했다.

- 모바일 메인은 프롬프트 영역을 기본으로 접고 이미지 중심으로 표시한다. 하단 생성 버튼 위 삼각형 영역으로 전체 프롬프트를 열고, 각각의 프롬프트도 접을 수 있다. 파라미터는 앱처럼 수치 슬라이더, 시드 잠금·랜덤 버튼, Anime/Furry 전환 버튼, 나란한 해상도·샘플러 항목과 토글로 정리했다. 실제 원본 이미지 없이 이전 인페인트 모드만 기억된 경우에는 인페인트 입력을 표시하거나 생성 프롬프트에 섞지 않으며 기존 저장 설정 자체는 변경하지 않는다.
- 사용자 요청에 따라 웹은 파일 자체가 10MB 이하인 원본 PNG/WebP를 재압축 없이 받는다. 암호화·base64 포장에 필요한 앱→웹 메시지 상한만 늘리고 웹→앱 명령 제한은 유지한다. 큰 연속 생성은 중계 전송량 제한을 넘지 않도록 송신 간격을 조절한다. 10MB 초과 시 임의 압축 대신 명확한 오류로 알리며 이미 생성된 PC 파일은 기존 저장 흐름대로 보존한다. 이전에 열린 웹은 기존 축소 미리보기를 계속 받을 수 있다. 임시 웹 히스토리는 최근 200장 또는 원본 총 100MB 중 먼저 도달한 범위만 유지하고 오래된 임시 URL을 정리한다. 기존 사용자 데이터·설정 schema 변경은 없다.
- 정확히 10MB 원본의 암호화 왕복·1바이트 초과 거절, 원본 전달의 canvas 우회, 인페인트 비활성 상태, 웹 입력·슬라이더·모드·시드·접기 동작과 히스토리 상한을 회귀 검사했다. 실제 Cloudflare 중계에서도 새 테스트 방에서 사용자 데이터 없는 18MB 프레임이 내용 변경 없이 전달되는 것을 확인하고 웹·Worker를 배포했다. 실제 휴대폰의 원본 이미지 생성·수신은 개발판 재시작 후 추가 확인이 필요하다. 앱·웹 빌드는 통과했고 lint는 기존 설정 누락으로 실행 실패했다.

- 모바일 메인 하단에 파라미터·이미지 생성·웹 히스토리 버튼을 배치했다. 최초 진입에 PC의 메인 프롬프트와 생성 파라미터, 모델별 옵션, 해상도 프리셋을 한 번 읽고 웹에서 편집한다. 파라미터 창 아래에서 1~100장의 생성 장수를 정하며, 모델별 Mode·Quality·UC·SMEA·투명 배경 지원은 앱 정의를 사용한다.
- 사용자 승인(2026-09-26)에 따라 웹에서 편집한 값은 원격 생성 요청에만 임시 적용한다. 기존 `nais2-forge-generation`의 저장 프롬프트·파라미터·시드·장수·모델별 기억값과 저장 schema는 변경하지 않는다. 현재 생성 함수가 persisted state를 직접 읽던 경계에 요청 전용 입력을 추가해 기존 공통 프롬프트 조립·전송·자동 저장·계정 전환·생성 지연 흐름을 재사용한다. 별도 migration·원본 변경·삭제는 없으며 코드를 되돌리면 기존 PC 설정으로 그대로 생성할 수 있다. 생성 결과 이미지·참조 캐시·실행 상태는 기존 생성 흐름대로 처리된다.
- 다중 생성은 한 번의 암호화된 명령으로 PC가 연속 실행하고, 각 이미지가 끝날 때마다 축소 미리보기를 웹에 전달한다. 웹 히스토리는 실제 PC 히스토리를 읽지 않고 웹에서 받은 최근 200장만 메모리에 유지하며 새로고침하면 비운다. 연결 폐기·만료·끊김 뒤에는 다음 회차를 시작하지 않고 이미 시작된 회차는 기존 생성 흐름대로 마친다.
- 생성 버튼의 비용은 PC와 같은 계산기를 사용한다. 생성 전에 PC가 입력 필드·모델·수치·해상도·장수를 검증하며, 설정 적용 확인은 핑에 의존하지 않고 기존 생성 접수 응답에 담는다. 최초 조회 이후 계정/참조/원본 등 비용 조건이 달라지면 생성을 시작하지 않고 최신 비용 조건을 알려 재확인하게 한다. 임의 명령·토큰·파일 경로는 원격 입력으로 허용하지 않는다.
- 새 회귀 검사에서 실제 생성 함수의 3장 요청과 매회 미리보기 전달, PC 설정의 serialization 보존, 이후 일반 생성, 연결 폐기 뒤 잔여 회차 중단, 잘못된 원격 입력·비용 변경 거절을 검증했다. 앱·웹 빌드와 기존 원격 프로토콜/중계/요청/탭 검사는 통과했다. lint는 기존 ESLint 설정 파일 누락으로 실행 실패하며, 실제 휴대폰–PC 생성 통합은 별도로 확인해야 한다. 실제 앱 버전은 1.12.0으로 유지한다.

- 생성 전에 중계 연결과 암호화된 PC 핑 응답을 확인한다. 연결·승인 응답·생성에는 각각 제한시간을 두고, 생성 중에도 PC 응답을 확인한다. PC가 꺼져 있거나 연결이 폐기된 경우 무한 대기하지 않으며, 시간 초과 뒤 생성 명령을 자동 재전송하지 않는다.
- 여러 웹 탭에서 동시에 요청하면 먼저 진행 중인 연결·생성 작업만 허용하고 나머지는 대기열에 넣지 않고 거절한다. PC에서도 생성 요청 접수와 생성 완료 대기를 분리해 생성 중 상태 확인에 답하고 중복 생성을 거절한다.
- 사용자 승인(2026-09-26)에 따라 기존 원격 연결 DB의 `sessions/active` 갱신을 원자적으로 처리하고, QR 재생성 시 이전 연결을 즉시 폐기한다. 폐기된 연결의 늦은 복호화·승인·저장·생성 완료가 연결을 되살리거나 새 기기에 결과를 보내지 못하게 한다. 이미 시작한 PC 생성은 계속될 수 있다. 기존 DB 이름·버전·필드·사용자 프롬프트·프리셋·이미지는 변경하지 않으며 migration은 없다. 폐기된 키는 백업하지 않고 새 QR 등록으로 연결을 복구한다. 새 웹의 핑에 응답하려면 수정된 PC 개발판을 다시 실행해야 한다.
- 프로토콜·중계 및 새 런타임 검사에서 암호화 왕복, 원자적 카운터, 폐기 이후 지연 저장 차단, 생성 중 핑, 중복 거절, 제한시간과 연결 종료 처리를 검증했다. 독립 정적 검토도 수행했다. 실제 휴대폰–PC의 이번 변경 통합 검증은 별도로 필요하며, lint는 기존 ESLint 설정 파일 누락으로 실행되지 않는다.

- 모바일 웹과 신규 QR의 접속 주소를 `https://ciyu.us/forge.web`로 정리했다. Worker가 기존 정적 페이지를 내부 반환하므로 주소와 QR fragment를 유지하며, 기존 `/index.html` 주소 및 등록 기기는 그대로 사용할 수 있다.

- 모바일 웹에 앱과 같은 홈·씬·스마트툴·설정 아이콘을 사용하는 상단 탭과 어두운 작업형 디자인을 추가했다. 기존 QR 연결·이미지 생성은 유지하며, 추가 탭의 내부 기능은 아직 연결하지 않았다. 웹은 계속 별도 폴더에 두고 앱 Git에 포함하지 않는다.

- PC 앱에서 QR을 발급하고 휴대폰 웹 한 대를 연결해 현재 메인 설정으로 이미지 한 장을 생성하는 실험 기능을 추가했다. 생성·원본 저장·NovelAI 인증 정보는 PC에 남고, 휴대폰에는 축소 미리보기만 전달한다. QR 등록 기한은 5분이며 연결 권한은 PC에서 입력한 1~72시간 동안 유효하다. PC에서 확인 코드를 대조해 승인하거나 즉시 연결을 해제할 수 있다.
- 별도 Cloudflare Worker 예제를 추가했다. Worker는 저장소 없이 접속 중인 두 기기의 암호문을 중계하며, 명령 내용·프롬프트·이미지·키를 해석하거나 보관하지 않는다. 무작위 라우팅 ID와 연결 메타데이터는 중계에 필요하고 제공업체에서 처리될 수 있다. 정적 웹은 앱 저장소에서 분리해 `C:\Users\admin\Desktop\Forge Web`에 두고 Git에 포함하지 않는다. `ciyu.us`의 `dev` 버킷, 중계는 `relay.ciyu.us`를 사용하도록 설정했다.
- 사용자 승인(2026-09-26)에 따라 기기별 비추출 암호화 키와 만료 시각만 별도 `nais2-forge-remote-pairing` IndexedDB에 저장한다. 기존 프롬프트·프리셋·이미지·설정 키와 스키마는 변경하지 않는다. 기존 데이터 migration·삭제는 없다. 연결 해제 시 새 연결 정보만 지우며, 기능을 되돌려도 기존 사용자 데이터는 그대로 보존된다. 브라우저 저장소가 지워지거나 업데이트로 origin이 바뀌면 다시 QR 등록이 필요할 수 있다.
- 이 단계는 공개 원격 제어 서비스의 보안 보증이 아니다. 정적 웹 자산을 제공하는 도메인과 스크립트가 신뢰되어야 하며, 배포 후에도 모바일 브라우저·Tauri 설치판 간 통합 및 공격 경로 검증이 필요하다.
- Worker는 `relay.ciyu.us`만 배포 도메인으로 선언하고 기본 `workers.dev` 및 미리보기 URL 노출을 비활성화했다.
- 공개 중계 경로의 남용을 줄이기 위해 Cloudflare 연결 요청 제한, Worker의 IP별 연결 제한, 연결별 암호문 메시지 수·크기 제한을 추가했다. 제한은 암호문 내용을 열지 않고 적용하며, 동일 공인 IP를 공유하는 사용자는 서로의 연결 한도에 영향을 줄 수 있다.
- `dev` R2 버킷에 별도 웹의 정적 파일만 게시하고 `https://ciyu.us/index.html` 및 두 자산의 HTTPS 응답을 확인했다. 새 Cloudflare 계정에 중계 Worker를 배포한 뒤 `wss://relay.ciyu.us`에서 무작위 테스트 키를 사용한 양방향 암호문 왕복을 검증했다. 사용자가 개발판 QR 연결·생성·휴대폰 결과 이미지 수신에 성공했으며 PC의 지정 저장 폴더에도 같은 시간대 PNG가 생성된 것을 확인했다. 배포 설치판·다른 기기에서의 범용 검증은 아직 수행하지 않았다.
